# Academy 10 人种子验证 Sprint

更新时间：2026-07-28

目标：用 10 名种子用户验证 Academy 是否真的能让用户在 21 天内持续学习、完成可验证证据，并至少产生 1 笔 $9.9 真实支付。

这不是增长活动，也不是大规模市场测试。它是一次 Founder-led Validation：用小样本确认学习闭环、提醒强度、课程难度、Evidence-first 机制和付费意愿是否成立。

---

## 1. 验证目标

首轮验证只回答 5 个问题：

1. 用户能不能连续 21 天坚持？
2. 用户是否能在 Day 7 前做出第一个可运行原型？
3. 用户是否能在 Day 21 前留下足够证据证明能力提升？
4. 用户是否接受 Telegram 提醒、追问、限制解锁和朋友监督？
5. 21 天结束后，是否至少 1 人愿意真实支付 $9.9 继续使用？

不在本轮回答：

- 是否可以规模化投放广告；
- 是否适合所有学习人群；
- 是否应该开放 Marketplace；
- 是否应该自动生成任意课程；
- 是否应该做完整 AI Runtime。

---

## 2. 样本定义

目标样本：10 人。

优先画像：

- 中国籍，生活在国外；
- 年龄 30–45 岁；
- 职业以 IT、运营、市场、个体户为主；
- 英语接近“几乎不能交流”到基础沟通；
- 对 AI 有兴趣，但不具备稳定工作流能力；
- 能接受 Telegram 提醒、连续学习天数、未完成任务追问、限制解锁下一课、朋友监督；
- 愿意先免费试用 21 天，结束后面对 $9.9/月付费选择。

排除样本：

- 只是帮忙注册、不愿学习；
- 不愿被提醒；
- 不愿提交证据；
- 完全不使用 Telegram；
- 明确没有 AI/英语/商业视角提升需求。

---

## 3. 成功标准

10 人中达到以下结果，才算首轮验证通过：

- 至少 3 人完成 21 天验证；
- 完成人每周至少有 5 个有效学习日；
- 完成人 21 天内至少有 15 个有效学习日；
- 至少 1 人真实支付 $9.9；
- 至少完成一次 Day 0 与 Day 21 能力对比；
- 记录每个完成日属于自主完成、提醒后完成，还是强监督后完成；
- 对 AI 模板用户，记录 FWPR-7；
- Day 21 至少 3 人满足模板 DoD，或明确记录为什么未达到。

判断口径：

- 注册不算有效用户；
- 打开 Mini App 不算有效学习；
- 只有 accepted evidence 才算有效学习行为；
- 使用积分抵扣的续费和无抵扣真实付费分开统计；
- 提醒或追问后完成同样计入留存，但必须标记完成来源；
- 提交证据、规则通过、人工复核通过不能混成一个完成率。

完成来源定义：

- 自主：未触发当日提醒前完成；
- 提醒：收到 Telegram 提醒后完成；
- 强监督：人工追问、朋友监督或多次催促后完成。

中断原因建议枚举：

- 忘记；
- 太难；
- 太简单；

- 页面/支付/登录 Bug；
- 课程内容不清楚；
- 不想继续；
- 其他。

## 6. Day 0 / Day 7 / Day 21 检查

### Day 0：Environment Ready

每个 AI 模板用户至少确认：

- [ ] 已选择 AI 课程；
- [ ] 已理解 21 天目标：Build a Personal Knowledge Assistant；
- [ ] 已准备一份测试文档；
- [ ] 已准备 3 个测试问题；
- [ ] 已完成 Day 0 evidence；
- [ ] Day 0 evidence 状态为 accepted。

### Day 7：First Working Prototype

每个 AI 模板用户至少确认：

- [ ] 提交 Demo / README / workflow 链接；
- [ ] 提交至少 3 个测试问题；
- [ ] 提交 expected answer；
- [ ] 提交 actual answer；
- [ ] 至少 2 条回答有来源/引用线索；
- [ ] 规则预检通过；
- [ ] 人工复核通过；
- [ ] 计入 FWPR-7。

### Day 21：Demo Day / DoD

每个 AI 模板用户至少确认：

- [ ] 原型可由第三方按说明运行；
- [ ] 至少 5 个围绕文档的问题通过测试；
- [ ] 提交 README；
- [ ] 提交 2 分钟 Demo；
- [ ] 提交测试结果；
- [ ] 提交失败边界说明；
- [ ] 人工复核通过；
- [ ] 计入 Day21 DoD。

## 10. 验证结论判定

### 通过

满足：

- 10 人招募完成；
- 至少 3 人完成 21 天；
- 至少 1 人真实支付 $9.9；
- FWPR-7 数据可解释；
- 失败原因已分类；
- 核心 Bug 不阻断学习；
- 用户愿意继续或推荐给同类人。

### 部分通过

满足部分留存，但未付费或 Day7 原型不足。

处理：

- 不急着扩课；
- 先改课程难度、提醒强度或 Evidence 提交流程；
- 再跑第二轮 10 人。

### 未通过

表现为：

- 10 人招不满；
- 大多数人 Day3 前流失；
- 用户无法理解每日任务；
- Day7 原型几乎没人完成；
- 没有人愿意付费；
- 用户反馈“像被迫打卡，但没有变强”。

处理：

- 暂停新增功能；
- 回到目标、用户画像、课程内容和监督强度重新校准；
- 不进入商业化投放。

## 11. 最小行动

下一步只做三件事：

1. 创始人自己按真机验收清单跑 7–10 天；
2. 填满 10 人招募表；
3. 第一个外部用户进入后，每天记录 evidence、提醒来源和中断原因。

建议在开始招募前先生成一份 cohort 记录：

```bash
npm run seed:new -- --cohort "seed-cohort-01" --operator "founder" --start-date "2026-08-01"
```

21 天结束后，把记录文件里的 machine-readable metrics 填完，并执行：

```bash
npm run seed:validate -- --file ../docs/seed-runs/<记录文件名>.md
```

只有当 `seed_result: pass`，且 10 人、3 人完成 21 天、1 人真实支付 $9.9、完成来源、不付费原因和核心阻断 Bug 都被记录后，才算首轮种子验证通过。否则只能判定为 partial 或 fail，不能直接扩课程或做增长投放。

## 12. 后台跟进记录入口

人工表格仍然用于招募和复盘，但每个种子用户的关键跟进记录应同步写入后台，避免只散落在 Telegram 私聊、纸面记录或临时笔记里。
系统落库表为 `seed_user_notes`。

后台读取入口：

```text
GET /api/academy/admin/ops-dashboard
```

后台写入入口：

```text
POST /api/academy/admin/ops-dashboard
Authorization: Bearer <ACADEMY_CRON_SECRET>
Content-Type: application/json
```

示例 payload：

```json
{
  "userId": "telegram:123456",
  "noteType": "failure_reason",
  "completionSource": "strong_supervision",
  "failureReason": "too_hard",
  "status": "watch",
  "content": "Day 3 卡在 AI 基本概念，完成是人工追问后完成；需要把课程正文讲得更细。",
  "recordedBy": "founder"
}
```

字段约定：

- `noteType`：`follow_up`、`failure_reason`、`payment_objection`、`manual_check`、`weekly_review`。
- `completionSource`：`self`、`reminder`、`strong_supervision`、`unknown`。
- `failureReason`：`forgot`、`too_hard`、`too_easy`、`unclear_task`、`not_enough_time`、`telegram_no_reminder`、`bug`、`content_unclear`、`not_willing`、`payment_failed`、`price`、`value_not_clear`、`other`。
- `status`：`open`、`watch`、`resolved`。

运营判断规则：

- 被催促后完成仍然计入留存，但必须记录 `completionSource=strong_supervision` 或 `reminder`。
- 不付费、掉队、课程太难、支付失败、提醒失败，都必须留下至少一条 seed note。
- 21 天复盘时，Dashboard 自动指标只回答“发生了什么”；seed note 用来回答“为什么发生”。
